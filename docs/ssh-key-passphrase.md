# Подключение MongoDB через SSH

В этом форке RustGrid поддерживает приватные SSH-ключи с парольной фразой.

Формат определяется по содержимому файла, а не расширению. Поддерживаются также старые
RSA PEM-ключи с `Proc-Type: 4,ENCRYPTED` и `DEK-Info: AES-256-CBC`: они расшифровываются
в памяти, исходный файл ключа не изменяется. Такой ключ может иметь расширение `.ppk`,
хотя его содержимое отличается от формата PuTTY.

На Mac приложение можно собрать командой:

```sh
sh packaging/macos/build-local.sh
```

Результат — `target/local/RustGrid SSH.app`. Установленная версия RustGrid не заменяется.
Для оптимизированной сборки передайте аргумент `release`.

Перед запуском этой сборки полностью завершите старый RustGrid через **Cmd+Q**. Программа
допускает только один запущенный экземпляр. Новая сборка использует существующий каталог
настроек; после сохранения подключений пользуйтесь ей, поскольку старые версии не умеют
восстанавливать новые зашифрованные пароли SSH.

1. На вкладке **Tunnel/Proxy** выберите **SSH tunnel**.
2. Укажите адрес сервера, SSH-порт и пользователя SSH.
3. В поле **Authentication** выберите **Private key file** и выберите приватный ключ через
   кнопку обзора. Файл с расширением `.pub` для этого не подходит.
4. Введите пароль ключа в поле **Private key passphrase** / **Парольная фраза SSH-ключа**.
   Для ключа без парольной фразы оставьте поле пустым.
5. На вкладке **General** укажите адрес MongoDB, доступный с SSH-сервера. Если база запущена
   на той же машине, это обычно `127.0.0.1`, порт `27017`. Для Docker нужен опубликованный
   на сервере порт либо адрес, доступный с SSH-сервера.
6. Укажите пользователя и пароль MongoDB. **Auth Database** — база, где создан пользователь;
   пустое поле означает `admin`.
7. Нажмите **Test Connection**, затем **Save & Connect**.

Ключ SSH-сервера должен совпадать с записью в `~/.ssh/known_hosts`. Если вы ещё не подключались
к этому серверу, сначала выполните `ssh -p ПОРТ ПОЛЬЗОВАТЕЛЬ@СЕРВЕР` в терминале и сверьте
показанный отпечаток ключа с администратором сервера перед подтверждением. Неизвестный или
изменившийся ключ RustGrid отклоняет до аутентификации.
Отозванные ключи также отклоняются. Сертификаты SSH-сервера и пользовательские пути
`UserKnownHostsFile` не поддерживаются; для них используйте системный SSH-туннель.

Парольная фраза расшифровывает ключ локально и не передаётся SSH-серверу. Поле скрывает вводимые
символы. При переключении между входом по ключу и входом по паролю значение очищается: это
разные учётные данные.

При сохранении подключения пароль SSH или парольная фраза ключа сохраняется в зашифрованном
хранилище `secrets.json`, отдельно от профиля подключения. Старые профили с паролями туннеля
в открытом виде переносят их в зашифрованное хранилище при следующем сохранении. Экспорт без
паролей не содержит учётных данных туннеля; экспорт с паролями защищает их так же, как пароль
базы данных.

У формата экспорта общий встроенный ключ шифрования: он скрывает пароли от беглого просмотра,
но не защищает их от получателя файла. Для передачи настроек другому человеку экспортируйте
их без паролей.

Недоступный SSH-сервер, неправильная парольная фраза и отказ в перенаправлении порта теперь
показываются как ошибки туннеля до подключения к MongoDB. Временный адрес вида
`127.0.0.1:55736` относится к внутреннему туннелю; копировать этот порт в настройки не нужно.

Встроенный SSH использует указанные в форме адрес, порт, пользователя и файл ключа. Он не
читает `~/.ssh/config` и не использует системный SSH-agent. Для этих возможностей можно
создать туннель системным `ssh` и отключить встроенный туннель в RustGrid.

## Исходящие запросы

При проверке сетевых путей исходников не обнаружена отправка введённых реквизитов или данных
таблиц разработчику либо сервисам аналитики. Приложение соединяется с настроенными серверами
БД/SSH/прокси, а также проверяет релизы и changelog на GitHub. В проверку обновлений не
передаются параметры подключения или содержимое базы; GitHub получает обычные сетевые
метаданные запроса, включая IP-адрес.

Эта проверка исходников не заменяет аудит всех сторонних библиотек или анализ сетевого трафика.
Запросы, вкладки и отчёты о сбоях могут сохраняться локально для работы и восстановления сеанса.
